# 병법36계 온톨로지 아키텍처 v2.0

## 목적

36개 독립 레코드를 고유 ID와 명시적 관계를 가진 지식 모델로 전환한다. 브라우저는 생성된 온톨로지 모델을 직접 읽어 지도·목록·상세·경로를 구성한다. 고사와 원전의 진위 검증, 전략 실행 권고, AI 추론 서비스는 포함하지 않는다.

## 계층과 파일

1. 원천 계층: `data/stratagems.json` 및 기존 CSV/JSONL/XLSX. 원문과 기존 필드를 수정하지 않는다.
2. 변환 계층: `scripts/build_ontology.py`. 원천 필드를 추출하고 명시적 전략 원리·상황 매핑을 결합한다. 동일 입력에 동일 출력과 고유 ID를 생성한다.
3. 의미 계층: `data/ontology.json` (UI용) 및 `data/ontology.jsonld` (RDF 교환용). 클래스·속성의 정의역/치역, 개체, 관계, 관계별 근거를 보유한다.
4. 탐색 계층: `assets/app.js`. 인접 목록, 유형/계열/관계 필터, 너비 우선 탐색(BFS)의 최단 경로, 검색을 제공한다. BFS는 방향을 무시하여 개체 사이의 연결을 찾되 화면 화살표에는 실제 관계 방향을 표시한다.
5. 표시 계층: `assets/graph.js`의 SVG와 `assets/style.css`. 계열별 배치, 원리 연결 배치, 1·2단계 중심 탐색, 선택·확대·이동·화면 맞춤 및 키보드 노드 선택을 지원한다.

## 개체 모델

| 클래스 | 수 | 의미 |
|---|---:|---|
| Stratagem | 36 | 원천 36개 계책, 원문·해석·통찰 전체 보존 |
| Family | 6 | 승전계·적전계·공전계·혼전계·병전계·패전계 |
| Principle | 10 | 편집자가 정리한 전략 원리 |
| Situation | 6 | 계열의 학습 맥락을 나타내는 편집 상황 |
| Tag | 104 | 원천 전략 태그의 정확히 일치하는 문자열만 병합 |
| Domain | 65 | 원천 적용 분야의 정확히 일치하는 문자열만 병합 |
| Case | 36 | 계책별 고사·사례 및 원천 출처유형 |
| Source | 1 | 원천 데이터의 공통 참고 URL |

총 264개 개체, 433개 명시적 관계. ‘기만’과 ‘심리기만’, ‘공급망’과 ‘공급망전략’ 등 유사 표현은 자동으로 동의어 처리하지 않는다. 전략 원리는 이들 원천 태그와 구분되는 별도 편집 계층이다.

## 관계 스키마

정의역은 모두 `Stratagem`이다.

| 속성 | 치역 | 수 | 근거 |
|---|---|---:|---|
| belongsTo | Family | 36 | 원천 계열 필드 |
| usesPrinciple | Principle | 72 | 원천 태그와 현대적 해석에 대한 편집 매핑 |
| suitedTo | Situation | 36 | 계열의 학습 맥락에 대한 편집 매핑 |
| hasTag | Tag | 109 | 원천 전략태그목록 |
| appliesTo | Domain | 108 | 원천 적용분야목록 |
| illustratedBy | Case | 36 | 원천 대표 출처/고사 |
| cites | Source | 36 | 원천 공통 출처 URL |

각 관계는 `id`, `source`, `relation`, `target`, `status`, `evidence`, `sourceDataset`을 가진다. 점선은 `status=interpretation`을 뜻한다. 실선은 원천 필드에서 추출했음을 뜻하며 역사적 사실을 검증했다는 의미가 아니다.

JSON-LD는 자체 namespace 아래 OWL 클래스와 ObjectProperty를 선언하고 RDFS domain/range를 정의한다. 관계를 RDF Statement로 구체화하여 근거, 상태 및 원천 커밋 URL을 함께 저장한다. 별도 OWL 추론기나 SPARQL 엔드포인트를 실행하지 않는다.

## 탐색 규칙

- 계열 지도: 계열·계책의 소속 관계를 표시한다. 계열 필터와 소속 관계 표시 여부를 적용한다.
- 원리 지도: 계책·전략 원리의 편집 매핑을 표시한다. 원리 관계를 해제하면 표시 관계가 없다.
- 선택 중심: 선택 개체에서 허용된 관계로 1·2단계 확장한다. 관계 방향과 무관하게 이웃을 찾아 표시하되, 화살표는 원래 방향을 유지한다.
- 관계 경로: 계열·원리·상황·태그·분야를 경유하는 무가중 최단 경로를 찾는다. 원리 관계를 우선 탐색하여 같은 길이에서는 개념적 연결이 먼저 보일 수 있다. 고사·공통 출처는 모든 계책을 의미 없이 연결하는 것을 피하기 위해 제외한다. 그래프 화면 필터와는 독립적이다.
- 경로는 인과관계, 효율 순위, 실행 순서 또는 추천 점수가 아니다.
- 관계의 출처 근거는 상세 패널, 관계 선 선택, 명제 표에서 확인할 수 있다.

## 데이터 갱신과 검증

```bash
python scripts/build_ontology.py
python tests/validate_ontology.py
node --check assets/app.js
node --check assets/graph.js
python -m http.server 8765
```

원천 변경 후 빌드 스크립트로 두 그래프 파일을 함께 재생성한다. 새 원천 버전을 사용할 때 `metadata.sourceCommit`, `sourceVersion`, `date`도 갱신한다. 검증은 원천 36개 레코드의 완전 보존, 1~36 번호의 유일성, 모든 참조의 존재, 관계 정의역/치역, 계열당 6개 계책, 편집 해석 표시, JSON-LD와 UI 모델의 일치를 검사한다.

## 운영

기존 GitHub Pages의 `gh-pages / root` 배포 경로를 사용한다. `main`과 `gh-pages`에 같은 검증된 커밋을 반영한다. 서버·유료 API·외부 CDN·분석 추적 스크립트·API 키를 추가하지 않았다. 데이터 요청은 동일 사이트의 정적 JSON 한 건이다. 입력 내용은 서버로 전송하거나 저장하지 않는다. 외부 참고자료 링크는 사용자가 클릭할 때만 열린다.

## 출처의 한계

기존 v1.1 데이터셋은 역사 기록, 소설, 전승, 현대적 해석을 포함한다. 이 전환은 해당 내용을 보존하며 개별 문헌의 정확성을 새로 검증하지 않았다. 공통 Wikipedia URL은 개요 참고자료이며 원전 판본, 고사 출처 또는 편집 원리 매핑의 직접 근거로 간주하지 않는다. 전략 원리 10개와 상황 6개는 분류 편의를 위한 해석이며 실제 적용 성공률이나 권고를 뜻하지 않는다.
